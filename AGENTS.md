# Instrucciones para Codex

Actúa como ingeniero de compiladores y firmware embebido. Este repositorio define PyPIC, un compilador AOT de un subconjunto de Python para la familia PIC completa (PIC16, PIC18, PIC24, dsPIC y PIC32; hoy el único destino implementado es el PIC16F887), con toolchain nativo independiente. No introduzcas MicroPython ni dependencia obligatoria de XC8. No afirmes que los módulos están implementados sin código/pruebas. Prioriza PIC16F887 y PIC14 clásica; segundo PIC12F625. Separa frontend/IR/backend/device packs/simulador/IDE. No asumas C++ soportado por XC8. Cada cambio debe incluir tests, documentación y criterios de aceptación. Verifica datasheets oficiales antes de codificar registros, pinout, configuración o instrucciones. Mantén compatibles las interfaces públicas y versiona esquemas. Implementa vertical slices pequeñas y reproducibles; antes de añadir features confirma que el HEX generado funciona en simulador y hardware cuando sea posible.

## RESTRICCIÓN NO NEGOCIABLE
**PyPIC solamente usa la sintaxis de Python; NO debe implementar, portar ni integrar un intérprete, VM o runtime Python en los PIC, ahora ni en versiones futuras.** La compilación y cualquier transpilación ocurren en el host; el MCU ejecuta exclusivamente firmware nativo. No propongas MicroPython, CircuitPython, CPython embebido, REPL ni ejecución de bytecode Python como solución. Una biblioteca mínima de rutinas nativas no equivale a intérprete. Consulta `docs/spec/00_PRINCIPIOS_NO_INTERPRETE.md` antes de modificar compilador o arquitectura.

## Principio de diseño
**PyPIC es un ensamblador de alto nivel**: lleva el código de ensamblador a alto nivel conservando la flexibilidad y la precisión de las instrucciones. Antes de añadir una función pregunta qué instrucción o idioma de ensamblador reemplaza y si conserva su control y su costo en ciclos; una sola forma por operación. Ver `docs/principios-de-diseno.md`.

Busca una experiencia de inicio comparable a Arduino sin renunciar al control del PIC: combina operaciones cómodas, primitivas, registros y ASM en sintaxis PIC-AS. Documenta esperas, efectos, recursos, costos y supuestos; no prometas ciclos exactos donde no exista tal contrato. Los valores automáticos deben poder ajustarse cuando el hardware lo requiera. Explica conflictos y límites sin ocultar recursos. Estas capacidades son objetivos, no pruebas de que estén implementadas. Ver `docs/spec/01_VISION.md`.
